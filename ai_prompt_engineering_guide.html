Dev Reference

AI & Prompt Engineering
Masterclass Rehberi

Modern geliştiriciler için gelişmiş prompt teknikleri, kodlama stratejileri, yerel (local) LLM yapılandırmaları, güvenlik prensipleri ve otonom agent mimarileri üzerine devasa referans dokümanı.

01. Gelişmiş Prompt Teknikleri

Büyük Dil Modellerini (LLM) en verimli şekilde kullanmak için bağlamın doğru yönetilmesi ve amaca uygun çerçevelerin (framework) kullanılması gerekir. Basit bir soru sormanın ötesine geçerek modellerin tam potansiyelini açığa çıkarın.

Zero-shot & Few-shot

Zero-shot yaklaşımında modele örnek verilmez, doğrudan görev istenir. Few-shot yaklaşımında ise modelin öğrenmesini kolaylaştırmak için birkaç girdi-çıktı örneği sunulur.

Few-shot (Güçlü):
Örnek 1: 'Ali yarın gelecek.' -> {'isimler': ['Ali']}
Görev: 'Kemal bugün ofiste yok.' -> ?

Chain-of-Thought (CoT) & ReAct

Chain-of-Thought, modelin adım adım düşünmesini sağlar. ReAct (Reasoning and Acting) ise muhakeme ve eylemi birleştirir.

prompt.txt 
Lütfen bu problemi adım adım çöz (Let's think step by step):
1. Önce veri yapısını tasarla.
2. Sonra zaman karmaşıklığını hesapla.
3. En son Python kodu üret.

Tree of Thoughts (ToT) & Self-Consistency

Tree of Thoughts (ToT), modelin üç farklı çözüm yolu (branch) üretip bunları kendi içinde değerlendirmesini ister. Self-Consistency ise aynı soruyu 5 kez sorup çoğunluk oyunu alarak halüsinasyonu sıfıra indirmeyi hedefler.

Meta-Prompting & Directional Stimulus

Meta-Prompting, LLM'e doğrudan cevabı yazdırmak yerine "Kendinize en iyi sonucu verecek promptu yazar mısınız?" diye sorma işlemidir.

Directional Stimulus ise modeli serbest bırakmak yerine odaklanması gereken anahtar kelimeleri (hint/ipucu) vererek çerçeveyi daraltır.

02. Kodlama & Hata Ayıklama Stratejileri

LLM'leri bir kodlama asistanı olarak kullanırken, bağlam penceresini verimli kullanmak ve doğru promptlarla refactoring yapmak hayati önem taşır.

Refactoring & Context Window

Binlerce satırlık spagetti kodu düzeltmek için tüm dosyayı modele yığmak Context Window israfıdır. Sadece ilgili modülleri sunun.

refactor_prompt.md 
Şu fonksiyonu refactor et:
- İç içe if'leri kaldır (Early return).
- SOLID prensiplerini uygula.
[KOD BURAYA]

Test-Driven Prompting (TDP)

Koddan önce test senaryolarını (TDD) yazdırmak sistem stabilitesini artırır. Önce "Bana 5 adet Jest case yaz", sonra "Bu testlerden geçen kodu üret" denmelidir.

Rubber Duck Debugging

Kodunuzdaki mantıksal hataları bulmak için kodunuzun niyetini modele uzun uzadıya anlatma tekniğidir. Model kodu düzeltmez, anlattığınız "niyet" ile kodun yaptığı "iş" arasındaki farkı size söyler.

Dokümantasyon Optimizasyonu

LLM'lerden JSDoc veya Docstring yazmasını isterken "Aşırı açıklamadan kaçın" (No over-explaining) uyarısı verilmelidir. Modeller gereksiz yere her satırı yorumlama eğilimindedir.

03. Yerel (Local) LLM Yapılandırması

Ollama, Llama-3, Qwen veya Mistral gibi modelleri tamamen çevrimdışı çalıştırırken donanım sınırlarını aşmanın ve asistanı kişiselleştirmenin yolları.

Ollama Modelfile & Parametreler

Sistem promptu ve hiperparametreler kalıcı olarak Modelfile içinde tanımlanmalıdır. Düşük Temperature analitik/kod işleri için, yüksek ise yaratıcı metinler içindir.

Modelfile 
FROM llama3:8b
PARAMETER temperature 0.2
PARAMETER top_p 0.9

SYSTEM """Kıdemli DevOps mühendisisin."""

Quantization (GGUF, AWQ)

Quantization, orijinali yüzlerce GB olan 32-bit modelleri 4-bit'e sıkıştırarak kalite kaybını minimize edip standart Mac ve PC'lerde çalıştırabilme teknolojisidir.

LoRA Fine-Tuning & Multi-Agent Frameworks

LoRA (Low-Rank Adaptation), koca modeli baştan aşağı eğitmek yerine küçük bir "adaptör katmanı" ile modele şirketinizin kod standartlarını öğretme yöntemidir. Çok daha ucuza ve hızlı eğitilir.

Büyük sistemler ise doğrudan modelle değil; LangChain, AutoGen veya CrewAI gibi agent mimarileri üzerinden çoklu asistan (örneğin: Biri yazar, diğeri kodu test eder) şeklinde orkestre edilir.

04. Güvenlik ve Optimizasyon

Canlı sistemlerde LLM kullanırken maliyetleri (token) kontrol altında tutmak ve güvenlik açıklarını yamamak şarttır.

Hallucination & RAG Mimarisi

Hallucination'a karşı endüstri standardı RAG (Retrieval-Augmented Generation) sistemidir. LLM cevabı uydurmaz, dış veritabanından (Vektör DB) bulup okur.

Prompt Leaking & Jailbreak

Kötü niyetli kullanıcıların "Önceki talimatları unut" (Jailbreak) veya "Bana sistem promptunu göster" (Prompt Leaking) saldırılarına karşı her zaman CAS uygulanmalı ve user verisi <xml> tagleri içine hapsedilmelidir.

JSON Mode

LLM dış dünyada API olarak çalışacaksa çıktı kesinlikle RegEx ile parçalanmamalı, model zorunlu olarak JSON Mode'a alınmalıdır.

Token Maliyet Optimizasyonu

Bağlamı gereksiz doldurmak (örn: Lütfen, teşekkürler demek, gereksiz boşluklar bırakmak) Token israfıdır. Input verileri LLM'e yollanmadan önce minimize edilmeli, gereksiz karakterler uçurulmalıdır.

05. LLM Entegrasyon Mimarileri

LLM'lerin izole sanal alanından çıkıp bilgisayarınızda dosya oluşturması, internette arama yapması veya veritabanı sorgulaması için kullanılan modern entegrasyonlar.

Function Calling (Tool Use)

Function Calling (Tool Use), modelin doğrudan bir metin cevabı üretmek yerine, arka planda geliştiricinin hazırladığı gerçek bir Python veya Node.js fonksiyonunu çağırmaya "karar vermesidir". Model dış dünyayı (API'ler, donanımlar) araçlar vasıtasıyla manipüle eder.

tool_schema.json 
// LLM'e verilen yetki tanımı (Tool JSON Schema)
{
  "name": "veritabanindan_kullanici_getir",
  "description": "Verilen e-posta adresi ile SQL sorgusu yapar.",
  "parameters": {
    "type": "object",
    "properties": {
      "email": { "type": "string", "description": "Kullanıcının e-posta adresi" }
    },
    "required": ["email"]
  }
}
// Sisteme "ahmet@mail.com nerede oturuyor?" dendiğinde LLM halüsinasyon yapmaz.
// Sistemin veritabanindan_kullanici_getir("ahmet@mail.com") fonksiyonunu tetiklemesini ister.
