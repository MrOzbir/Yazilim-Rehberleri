Bölüm 01

C# Temelleri ve OOP Kavramları

İleri seviye konulara geçmeden önce, C# ve .NET mimarisinin üzerine inşa edildiği temel yapı taşlarını, bellek yönetiminin temellerini ve Nesne Yönelimli Programlama (OOP) prensiplerini eksiksiz anlamak kritik önem taşır.

1. Stack vs Heap ve Tip Mimarisi

C#'ta bellek yönetimi ve değişkenlerin saklanma biçimi (Memory Allocation) iki ana bölgeye ayrılır: Stack ve Heap.

  • Value Types (Değer Tipleri): struct, enum, int, double, bool gibi tiplerdir. Doğrudan veriyi içerirler ve kural olarak Stack'te tahsis edilirler. İşlem bittiğinde anında bellekten silinirler (Garbage Collector beklemez).
  • Reference Types (Referans Tipleri): class, string, interface, delegate, array gibi tiplerdir. Verinin kendisi Heap'te tutulur, Stack'te ise sadece bu veriyi gösteren bellek adresi (Pointer/Referans) yer alır. Heap'teki verinin temizlenmesi Garbage Collector'ın (GC) sorumluluğundadır.
// 1. Değer Tipi Kopyalama (Tamamen bağımsız iki değişken oluşur)
int a = 10;
int b = a; 
b = 20; // 'a' bu değişiklikten etkilenmez, hala 10'dur.

// 2. Referans Tipi Kopyalama (Sadece bellek adresi kopyalanır)
List<int> list1 = new List<int> { 1, 2 };
List<int> list2 = list1; 
list2.Add(3); // list1 ve list2 aynı bellek adresini (Heap objesini) gösterdiği için list1 de değişir!
Kritik Uyarı (Boxing/Unboxing): Bir değer tipini (örn. int) referans tipine (örn. object) atamak "Boxing" işlemidir. Bu, değişkeni alıp Heap'te yeni bir kutuya koyar. Sürekli boxing/unboxing yapmak performansı ciddi şekilde düşürür (GC'yi yorar).

2. Parametre Aktarım Yöntemleri (ref, out, in)

Varsayılan olarak değer tipleri metoda "kopyalanarak" (by value), referans tiplerinin de "referansının kopyası" aktarılarak yollanır. Bu davranışı değiştirmek mümkündür:

  • ref: Değişkenin orijinal bellek adresini metoda yollar. Metot içindeki değişiklik orijinal değişkeni etkiler. Değişkenin metoda verilmeden önce başlatılmış (initialize) olması zorunludur.
  • out: ref ile aynıdır, ancak değişkene metoda girmeden değer atanmak zorunda değildir. Metodun, değişkeni mutlaka dolduracağı garanti edilir (Örn: int.TryParse).
  • in: ref gibi bellek adresini yollar ancak salt okunurdur (readonly). Sadece büyük struct'ları kopyalama maliyetinden kurtarmak için performans amaçlı kullanılır.

3. OOP: Encapsulation (Kapsülleme) ve Erişim Belirleyiciler

Bir sınıfın verilerini (fields) dışarıdan gelebilecek kontrolsüz müdahalelere kapatma işlemidir.

  • public: Her yerden erişilebilir.
  • private: Yalnızca tanımlandığı sınıf (class) içinden erişilebilir.
  • protected: Kendi sınıfı ve miras alan (inherit eden) alt sınıflardan erişilebilir.
  • internal: Sadece aynı DLL/Proje (Assembly) içinden erişilebilir.
public class User
{
    // Field (Özel alan)
    private int _age; 

    // Property (Özellik) - Getter ve Setter ile mantık yürütme
    public int Age 
    {
        get { return _age; }
        set 
        { 
            if (value < 0) throw new ArgumentException("Yaş negatif olamaz.");
            _age = value; 
        }
    }

    // Auto-property (Derleyici arka planda private field oluşturur)
    public string Name { get; set; }
    
    // Init-only Property (C# 9) - Nesne sadece new ile yaratılırken atanabilir, sonra değiştirilemez!
    public DateTime CreatedAt { get; init; } = DateTime.UtcNow;
}

4. OOP: Kalıtım (Inheritance) ve Çok Biçimlilik (Polymorphism)

Kalıtım, bir sınıfın (Base) özelliklerini başka bir sınıfa (Derived) aktarmasıdır. C#'ta bir sınıf sadece TEK BİR sınıftan miras alabilir.
Çok Biçimlilik (Polymorphism), alt sınıfların üst sınıfın metotlarını ezerek (override) kendilerine özgü davranış sergileyebilmesidir.

public class Animal
{
    // virtual: Alt sınıflar dilerse bu metodu değiştirebilir
    public virtual void MakeSound() => Console.WriteLine("Sessizlik...");
}

public class Dog : Animal
{
    // override: Üst sınıftaki 'virtual' metodu eziyoruz
    public override void MakeSound() => Console.WriteLine("Hav hav!");
}

// Polimorfizm kullanımı:
Animal myPet = new Dog();
myPet.MakeSound(); // Çıktı: "Hav hav!" (Animal tipinde tutulsa da Dog'un metodu çalışır)

5. Soyutlama (Abstraction): Interface vs Abstract Class

Soyutlama, karmaşıklığı gizleyip sadece gerekli arayüzü sunma işlemidir.

  • Interface (Arayüz): Gövdesiz metot tanımlarıdır ("Sözleşme"). Bir sınıf birden fazla interface uygulayabilir (Çoklu Kalıtım). Dependency Injection'ın bel kemiğidir. C# 8.0 ile Default Interface Methods (Gövde barındıran metotlar) desteklenmeye başlamıştır.
  • Abstract Class (Soyut Sınıf): Yarı şablon, yarı gerçek sınıftır. Hem ortak kod yazabilirsiniz hem de alt sınıfların doldurmasını zorunlu tutacağınız abstract metotlar tanımlayabilirsiniz. new ile doğrudan yaratılamazlar.
public interface ILogger 
{ 
    void LogInfo(string msg);
    // C# 8 Default Interface Method:
    void LogError(string msg) => Console.WriteLine("ERROR: " + msg); 
}

public abstract class BaseRepository
{
    protected string ConnectionString { get; set; }
    
    // Ortak dolu metot
    public void OpenConnection() { /* ... */ }
    
    // Alt sınıfların mecburen yazacağı soyut metot
    public abstract void Save(); 
}

6. Hata Yönetimi (Exceptions)

Uygulama çalışırken oluşan istisnai durumları yakalamak için try-catch-finally kullanılır.

try 
{
    int result = 10 / int.Parse("0");
}
catch (DivideByZeroException ex) 
{
    Console.WriteLine("Sıfıra bölme hatası: " + ex.Message);
    throw; // Hatayı yutmadan üst katmana (çağrıldığı yere) fırlatır (Call stack korunur)
}
catch (Exception ex)
{
    // Diğer tüm hatalar
}
finally 
{
    // Hata olsun veya olmasın her zaman çalışır (Örn: Veritabanı bağlantısı kapatmak için)
    Console.WriteLine("İşlem bitti.");
}

7. Generics (Jenerikler)

Aynı mantığı farklı tipler için (tip güvenli şekilde) tekrar tekrar yazmanızı önler. Boxing/Unboxing sorununu kökten çözer.

// 'T' burada jenerik tiptir. Kullanılırken belirlenir.
public class Repository<T> where T : class, new() // Kısıtlamalar (Constraints)
{
    public T CreateNewInstance()
    {
        // T'nin class (referans tip) ve parametresiz constructor'a sahip olduğu garanti edilmiştir
        return new T(); 
    }
}

var userRepo = new Repository<User>(); // T yerine 'User' geçer.

8. Delegates ve Fonksiyonel C# (Action, Func)

C#'ta metotları bir değişkene atamak veya başka metotlara parametre olarak yollamak için Delegate (Temsilci) kullanılır. Modern C#'ta özel delegate tanımlamak yerine yerleşik (built-in) yapılar kullanılır:

  • Action<T>: Parametre alır, ancak geriye değer dönmez (void).
  • Func<T, TResult>: Parametre alır ve geriye bir değer döner. Son parametre dönüş tipidir.
  • Predicate<T>: Bir tip alır ve her zaman bool (true/false) döner (Genelde filtreleme için).
// Func örneği: (int x, int y) alır, 'string' döner
Func<int, int, string> calculateAndFormat = (x, y) => $"Sonuç: {x + y}";
Console.WriteLine(calculateAndFormat(5, 10)); // Çıktı: "Sonuç: 15"

// Action örneği (Dönüş tipi void)
Action<string> print = msg => Console.WriteLine(msg);
print("Merhaba Fonksiyonel C#!");
Bölüm 02

Asenkron Programlama Derinlemesine

C#'ın async/await modeli aslında derleyici seviyesinde devasa bir state machine (durum makinesi) oluşturur (IAsyncStateMachine). Arka planda thread bloklanmaz; bunun yerine görev tamamlandığında ThreadPool'dan uygun bir thread devam işlemlerini (continuation) yürütür.

1. Task vs ValueTask ve Senkron Tamamlanma

Task bir referans tipidir (class). Her metot çağrısında heap'te tahsis (allocation) edilir. Ancak, metodunuz sıklıkla senkron tamamlanıyorsa (örneğin veriyi cache'ten okuyorsa), gereksiz heap alokasyonlarından kaçınmak için değer tipi (struct) olan ValueTask kullanılmalıdır.

public async ValueTask<int> GetDataAsync(string key)
{
    // Veri cache'te varsa (Senkron tamamlanma - Sıfır Heap Allocation)
    if (_cache.TryGetValue(key, out int value))
        return value;

    // Aksi halde asenkron operasyon çalışır (Task'e düşer)
    return await FetchFromDatabaseAsync(key);
}
Kritik Uyarı: ValueTask'i asla birden fazla kez await etmeyin ve aynı anda birden fazla thread'den beklemeyin (Task.WhenAll içine doğrudan vermeyin, .AsTask() ile çevirin). Arkasındaki nesne havuza geri dönmüş ve başka bir işlem için kullanılıyor olabilir.

2. Task.WhenAll ve Hata Yönetimi (Exception Aggregation)

Bağımsız işlemleri paralel yürüterek I/O bekleme süresini minimize edin. Task.WhenAll tüm task'lerin bitmesini bekler. Hata oluştuğunda sadece ilk hatayı fırlatır, tüm hataları görmek için Task.Exception.InnerExceptions kontrol edilmelidir.

var userTask = GetUserAsync(id);
var ordersTask = GetOrdersAsync(id);
var pointsTask = GetLoyaltyPointsAsync(id);

try {
    // 3 asenkron ağ çağrısı aynı anda başlar ve paralelde beklenir
    await Task.WhenAll(userTask, ordersTask, pointsTask);
    
    // İşlem bittiğinde Result'lara güvenle senkron erişilir
    var response = new UserDashboard(userTask.Result, ordersTask.Result, pointsTask.Result);
} catch (Exception ex) {
    // Yalnızca İLK fırlatılan exception buraya düşer.
}

3. Task.WhenAny ile Zaman Aşımı (Timeout) İmplementasyonu

Bir işlemin belli bir sürede tamamlanmasını zorlamak için Task.Delay ile birlikte Task.WhenAny harika bir çözümdür.

var fetchTask = FetchHugeDataAsync();
var timeoutTask = Task.Delay(TimeSpan.FromSeconds(5));

var completedTask = await Task.WhenAny(fetchTask, timeoutTask);

if (completedTask == timeoutTask) {
    throw new TimeoutException("Veri çekme işlemi 5 saniyeyi aştı!");
}
var data = await fetchTask; // Güvenle sonucu al

4. ConfigureAwait(false) ve Deadlock'lardan Kaçınma

UI frameworklerinde (WPF, WinForms) veya eski ASP.NET projelerinde SynchronizationContext mevcuttur. Bir kütüphane geliştiriyorsanız, UI thread'ini kitlememek ve performansı artırmak için daima ConfigureAwait(false) kullanın.

public async Task<string> DownloadContentAsync(string url)
{
    using var client = new HttpClient();
    // İşlem bittiğinde orjinal thread'e dönmeye zorlamaz (Threadpool threadinden devam eder)
    var response = await client.GetAsync(url).ConfigureAwait(false);
    return await response.Content.ReadAsStringAsync().ConfigureAwait(false);
}

5. IAsyncEnumerable Akışları

Devasa bir dosyayı okurken listeyi tamamen belleğe (List<T>) doldurmak yerine parça parça işlemek asenkron akışlarla mümkündür. Yield return ile asenkron iteratör yazılır.

public async IAsyncEnumerable<LogEntry> StreamLogsAsync([EnumeratorCancellation] CancellationToken ct = default)
{
    using var reader = File.OpenText("server.log");
    string line;
    while ((line = await reader.ReadLineAsync().WaitAsync(ct)) != null)
    {
        yield return ParseLog(line); // Her bir satır okundukça yield edilir
    }
}

// Tüketim noktası:
await foreach (var log in StreamLogsAsync(cancellationToken)) {
    Console.WriteLine(log.Message); // Memory şişmez!
}
Bölüm 03

Bellek Yönetimi & Performans İpuçları

C# bir Garbage Collector (GC) dilidir. Yüksek performanslı uygulamaların en büyük düşmanı sık GC tetiklenmesidir. "Zero-allocation" (sıfır bellek ayırma) mimarisi modern C# ile çok kolaylaşmıştır.

1. Span<T> ve ReadOnlySpan<T>

Metin (string) veya Array (dizi) operasyonlarında Substring kullanmak yeni bir metin objesi oluşturur. Span<T>, hafızadaki mevcut bloğa (heap, stack veya unmanaged bellek) pencere (view) açarak sıfır alokasyon sağlar.

string record = "KUTAY;1995;ACTIVE";

// KÖTÜ: Substring() yüzünden heap'te 2 yeni string nesnesi oluşturulur.
string yearStr = record.Substring(6, 4); 
int year = int.Parse(yearStr);

// İYİ: Mevcut string'in belleğine salt okunur bir pencere açılır (Allocation yok!)
ReadOnlySpan<char> recordSpan = record.AsSpan();
ReadOnlySpan<char> yearSpan = recordSpan.Slice(6, 4);
int year2 = int.Parse(yearSpan);

2. 'ref struct' Limitleri ve Memory<T>

Span<T> bir ref struct'tır. Yani sadece Stack'te yaşayabilir (Heap'e çıkamaz). Bu yüzden async/await metotları içerisinde (state machine heap'e taşındığı için) Span KULLANILAMAZ. Çözüm Memory<T>'dir.

public async Task ProcessDataAsync(Memory<byte> buffer)
{
    // Memory<T> heap'te yaşayabildiği için await noktasından geçebilir
    await _networkStream.ReadAsync(buffer);
    
    // Senkron (ve hızlı) veri işleme safhasında Span'a dönüştürülür:
    ProcessInternal(buffer.Span); 
}

3. Stackalloc ile Stack Bellek Kullanımı

Küçük byte veya char dizilerine ihtiyacınız varsa array (new int[100]) oluşturup heap'i kirletmek yerine, metot sonlandığında anında temizlenen stack'i kullanın.

public void GenerateShortHash()
{
    // Heap yerine o anki metodun stack framinden 64 byte alır
    Span<byte> hashBuffer = stackalloc byte[64];
    
    // Buffer doldurulur ve işlenir. GC'ye iş düşmez!
    RandomNumberGenerator.Fill(hashBuffer);
    Compute(hashBuffer);
}

4. LOH (Large Object Heap) ve ArrayPool

85.000 byte'tan (yaklaşık 85KB) büyük nesneler doğrudan LOH'a gider. LOH, klasik GC mantığında olduğu gibi defragmantasyon (sıkıştırma) yapmaz ve performans sorunları yaratır. Büyük diziler için daima ArrayPool kullanın.

public void ProcessImage(int size)
{
    // KÖTÜ: 100KB'lık byte array = LOH alokasyonu
    // byte[] buffer = new byte[100000];

    // İYİ: Havuzdan ödünç al (Allocation yok, GC baskısı sıfır)
    byte[] buffer = ArrayPool<byte>.Shared.Rent(100000);
    try
    {
        // Havuz boyutu istediğinizden büyük olabilir, Span ile sınırlandırın
        Span<byte> exactSpan = buffer.AsSpan(0, 100000);
        FillImagePixels(exactSpan);
    }
    finally
    {
        // Mutlaka havuza iade edin!
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
Bölüm 04

LINQ Derinlemesine

1. Deferred Execution (Ertelenmiş Çalışma)

LINQ'nun filtre metotları (Where, Select, OrderBy vb.) doğrudan çalışmaz, sadece bir sorgu planı (Expression/Iterator) döndürürler. Ancak değerleri dışarı çıkaran (ToList(), First(), Count() veya foreach) metotlar tetiklendiğinde query çalışır.

var numbers = new List<int> { 1, 2, 3 };

// Sorgu planı hazırlandı, DÖNGÜ ÇALIŞMADI!
var query = numbers.Where(n => n > 1); 

numbers.Add(4); // Ana listeye ekleme yaptık

// ŞİMDİ query çalışıyor. Sonuç: 2, 3, 4
// Eğer 'query' listeye çevrilseydi (ToList), 4'ü görmeyecektik.
foreach(var item in query) {
    Console.WriteLine(item);
}
Çoklu Çalışma Tuzağı: Bir LINQ sorgusu üzerinde .Count() ve ardından .ToList() çağırırsanız veritabanına VEYA bellek içi koleksiyona o sorguyu 2 kere çalıştırmış olursunuz.

2. IEnumerable vs IQueryable

En büyük mimari hatalardan biri ORM'ler (Entity Framework vb.) ile çalışırken yanlış filtreleme zinciri kurmaktır.

  • IQueryable: Arka planda yazdığınız C# kodunu SQL, MongoDB veya REST sorgularına çeviren bir Expression Tree oluşturur.
  • IEnumerable: Yalnızca elinizdeki hazır liste/hafıza üzerinde gezinmek içindir, veriyi çektikten SONRA bellekte C# ile filtreler.
// KÖTÜ ÖRNEK: Tablodaki 1 milyon kaydı RAM'e çeker (.AsEnumerable() veya .ToList() ile)
// ve C# RAM'inde filtrelemeye çalışır.
var activeUsers = dbContext.Users.AsEnumerable().Where(u => u.IsActive).ToList();

// İYİ ÖRNEK: Expression tree kullanarak şu SQL'i üretir: "SELECT * FROM Users WHERE IsActive = 1"
// Yalnızca dönen aktif kullanıcılar RAM'e yerleşir.
var activeUsers = dbContext.Users.Where(u => u.IsActive).ToList();

3. Any() vs Count() > 0

Bir koleksiyonda eleman olup olmadığını kontrol etmek için Count() kullanmak felakettir (Özellikle IQueryable ve SQL ile). Any() ilk kaydı bulduğunda döngüyü keser.

// KÖTÜ: "SELECT COUNT(*) FROM Users" sorgusu atar, tüm tabloyu tarar
if (dbContext.Users.Count() > 0) { ... }

// İYİ: "SELECT TOP 1 1 FROM Users" (veya "EXISTS") atar, performansı inanılmaz artırır
if (dbContext.Users.Any()) { ... }

4. PLINQ (AsParallel)

CPU bound (matematiksel vb.) büyük işlemlerde CPU'nun çoklu çekirdeklerini kullanmak için LINQ'yu paralel hale getirebilirsiniz.

// Tüm çekirdekleri kullanarak listeyi aynı anda işler
var heavyResults = largeDataList
    .AsParallel()
    .WithDegreeOfParallelism(Environment.ProcessorCount)
    .Where(x => IsPrimeNumber(x))
    .ToList();
Bölüm 05

Modern C# Özellikleri ve Refactoring

1. Records (C# 9)

class yapısı reference-based (referans) eşitliği sağlar, yani içerikleri aynı olsa da RAM'deki adresleri farklıysa nesneler eşit değildir. record ise otomatik olarak value-based (değer) eşitlik sağlar (ve Deconstruct destekler).

public record CustomerDto(int Id, string Name);

var c1 = new CustomerDto(1, "Ahmet");
var c2 = new CustomerDto(1, "Ahmet");

Console.WriteLine(c1 == c2); // Sınıf(class) olsaydı FALSE, Record olduğu için TRUE!

// 'with' keyword'ü ile immutable nesne kopyalama
var c3 = c1 with { Name = "Mehmet" }; // Id=1, Name=Mehmet

2. Primary Constructors (C# 12)

Artık her servisin veya sınıfın tepesinde constructor yazmak zorunda değilsiniz, sınıf imzasına parametreler verebilirsiniz. Dependency Injection kodlarını inanılmaz kısaltır.

// ESKİ YÖNTEM:
public class UserService 
{
    private readonly IUserRepository _repo;
    public UserService(IUserRepository repo) { _repo = repo; }
}

// YENİ YÖNTEM (C# 12):
public class UserService(IUserRepository repo, ILogger<UserService> logger)
{
    public void DeleteUser(int id)
    {
        // Doğrudan 'repo' ve 'logger' değişkenlerini kullanabilirsiniz.
        logger.LogWarning("{Id} siliniyor...", id);
        repo.Delete(id);
    }
}

3. İleri Düzey Pattern Matching (Switch Expressions)

İç içe geçmiş if-else veya uzun switch-case bloklarını mükemmel, okunabilir ve kısa fonksiyonel ifadelere çevirir.

public string EvaluateOrder(Order order) => order switch
{
    // Property Pattern & Logical Pattern
    { Status: "Pending", Amount: > 1000 } => "Büyük Bekleyen Sipariş",
    
    // Type Pattern (Miras alınan veya interfaceden gelen tipleri kontrol etme)
    DigitalOrder digi when digi.SizeMb > 100 => "Büyük Dosya İndirmesi",
    PhysicalOrder { WeightGrams: < 500 } => "Küçük Kargo",
    
    // List Pattern (Özellikle Parser yazarken dizilerin içini analiz eder)
    { Items: ["Laptop", "Mouse", ..] } => "Bilgisayar Paketi Kampanyası",
    
    // null kontrolü
    null => throw new ArgumentNullException(nameof(order)),
    
    // Fallback (default)
    _ => "Standart Sipariş"
};

4. Collection Expressions (C# 12)

Dizileri veya Listeleri ilklendirmek çok daha temiz hale geldi (Spread operatörü .. dahil edildi).

int[] arr1 = [1, 2, 3];
int[] arr2 = [4, 5, 6];

// İki diziyi birleştirme (JS spread operatörüne benzer)
int[] combined = [..arr1, 99, ..arr2]; // [1, 2, 3, 99, 4, 5, 6]

// Liste veya Span dönerken
List<string> names = ["Alice", "Bob"];
Span<int> values = [10, 20, 30]; // Derleyici stackalloc'a optimize edebilir!
