İleri Seviye Yazılım Mimarisi & Temiz Kod Rehberi

Modern yazılım geliştirme süreçlerinde sürdürülebilir, ölçeklenebilir ve temiz kod yazım sanatına dair kurumsal standartlar ve pratikler bütünü.

01 SOLID Prensipleri

Single Responsibility Principle (SRP)

Bir sınıfın değişmesi için yalnızca bir nedeni olmalıdır. Her sınıf veya modül tek bir sorumluluğa odaklanmalıdır.

Kötü Pratik (Code Smell)
class UserManager {
  public createUser(user: User): void {
    // Veritabanına kaydet
    db.save(user);
    // E-posta gönder
    const emailHtml = `<h1>Hoşgeldin ${user.name}</h1>`;
    smtp.send(user.email, emailHtml);
  }
}
İyi Pratik (Clean Code)
class UserRepository {
  public save(user: User): void { db.save(user); }
}

class EmailService {
  public sendWelcomeEmail(user: User): void {
    smtp.send(user.email, `<h1>Hoşgeldin ${user.name}</h1>`);
  }
}

Open/Closed Principle (OCP)

Yazılım varlıkları (sınıflar, modüller, fonksiyonlar) gelişime açık, değişime kapalı olmalıdır.

Kötü Pratik (Code Smell)
function calculateArea(shape: any) {
  if (shape.type === 'circle') {
    return Math.PI * shape.radius ** 2;
  } else if (shape.type === 'square') {
    return shape.side ** 2;
  }
}
İyi Pratik (Clean Code)
interface Shape { calculateArea(): number; }

class Circle implements Shape {
  constructor(private radius: number) {}
  calculateArea() { return Math.PI * this.radius ** 2; }
}

class Square implements Shape {
  constructor(private side: number) {}
  calculateArea() { return this.side ** 2; }
}

02 Clean Code Temelleri

Guard Clauses (Koruma İfadeleri)

Arrow Anti-Pattern olarak bilinen iç içe geçmiş `if` bloklarından kaçının. Hatalı veya geçersiz durumları fonksiyonun başında tespit edip erken dönüş (early return) yapın.

İç İçe İfadeler (Anti-Pattern)
function processOrder(order: Order) {
  if (order != null) {
    if (order.isVerified) {
      if (order.items.length > 0) {
        // Ana mantık burada
        paymentGateway.charge(order);
      }
    }
  }
}
Guard Clauses (Temiz Akış)
function processOrder(order: Order) {
  if (!order) return;
  if (!order.isVerified) return;
  if (order.items.length === 0) return;

  // Ana mantık temiz ve düz
  paymentGateway.charge(order);
}

Anlamlı İsimlendirmeler (Naming Standards)

Değişkenler ve fonksiyonlar niyetlerini açıkça belli etmelidir. Yorum satırlarına ihtiyaç bırakmayan isimlendirmeler tercih edilmelidir.

Kötü Pratik
let d: number; // Geçen gün süresi
const users = getUsers();
const filtered = users.filter(u => u.a >= 18);
İyi Pratik
let elapsedTimeInDays: number;
const registeredUsers = fetchRegisteredUsers();
const adultUsers = registeredUsers.filter(
  user => user.age >= 18
);

03 Tasarım Kalıpları

Strategy Pattern (Strateji Kalıbı)

Bir algoritma ailesini tanımlar, her birini kapsüller ve birbirlerinin yerine kullanılabilir hale getirir.

interface PaymentStrategy {
  pay(amount: number): void;
}

class CreditCardPayment implements PaymentStrategy {
  pay(amount: number) { console.log(`Paid ${amount} via Credit Card`); }
}

class PayPalPayment implements PaymentStrategy {
  pay(amount: number) { console.log(`Paid ${amount} via PayPal`); }
}

class ShoppingCart {
  constructor(private strategy: PaymentStrategy) {}
  
  checkout(amount: number) {
    this.strategy.pay(amount);
  }
}

// Kullanım:
const cart = new ShoppingCart(new PayPalPayment());
cart.checkout(100); // "Paid 100 via PayPal"

04 Teknik Borç (Technical Debt)

Boy Scout Rule (İzci Kuralı)

"Kamp alanını bulduğundan daha temiz bırak."

Her kod incelemesinde veya düzenlemesinde, mevcut özellik üzerinde çalışırken karşılaştığınız ufak pürüzleri (isimlendirme hataları, gereksiz boşluklar, ufak refaktörler) giderin. Teknik borç birikimini engellemenin en sürdürülebilir yoludur.

Otomatize Code-Review (CI/CD Pipelines)

İnsan gözüyle bulunabilecek basit hataları (syntax, formatting) tartışmak zaman israfıdır. Bunlar için automated pipeline'lar kurulmalıdır:

  • Linter: ESLint, SonarQube entegrasyonu.
  • Formatter: Prettier (On commit hook).
  • Test Coverage: Minimum %80 kuralı (Jest, xUnit).
